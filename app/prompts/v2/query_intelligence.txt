You are analyzing a user query sent to an Amazon device support bot. The bot supports Kindle e-readers only.

Query: {query}

Recent conversation history:
{session_history}

Analyze the query and return a JSON object with these fields:

- intent: one clear sentence describing what the user is trying to accomplish
- sub_queries: a list of distinct questions within the query. If there is only one question, return a list with one item. Do NOT split a single question into multiple sub_queries.
- complexity: "low" if this is a straightforward factual or how-to question (e.g. "how do I connect Kindle to WiFi", "how do I restart Fire TV"). "high" if it requires multi-step reasoning, policy knowledge, troubleshooting with many possible causes, or questions spanning both devices.
- needs_decomp: true only if there are 2 or more genuinely distinct sub_queries that should be answered independently. false otherwise.
- relevant_docs: list of document IDs to search based on which device the query is about.
  - Use ["kindle"] if the query is clearly about a Kindle device.
  - Use ["firetv"] if the query is clearly about a Fire TV device.
  - Use ["kindle", "firetv"] if the query mentions both devices, or is ambiguous but still Amazon device related (e.g. "how do I connect to WiFi" without mentioning a specific device).
  - Use [] if the query is completely unrelated to Kindle or Fire TV (e.g. weather, cooking, general knowledge).
  - Use [] if the query is a greeting, introduction, or too vague to retrieve anything useful (e.g. "hi", "hello", "kindle", "help me"). No docs are needed when there is no specific question to answer.
- is_cacheable: true only if the query is a factual, context-free question whose answer would be the same for any user. false if the query references prior conversation ("what if that doesn't work?", "what about the second option?"), is personal ("hi my name is Sagrika"), is too specific to a user's situation, or is a troubleshooting follow-up.
